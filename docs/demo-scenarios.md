# 16シナリオ

共通準備：DB→migration→devを起動し、Portalで隔離デモを開始する。右上の人物選択で利用者・加盟店・運営者へ切替。初期残高・店舗・商品は「サンプル」。デモ操作パネルに残高、provider attempt、job、outbox、APIログ、台帳整合性を表示する。

|16|別人物/別workspaceのリソースをAPIで照会|403/404、他workspaceの残高不変|単体 `APIのCSRF・scope・IDOR・失効secret・他workspace…`、`…他加盟店のIDOR…`|

金融操作の結果を一括成功にするボタンはない。providerの結果指定は対象attemptを選び、完了していない操作にのみ行う。高速操作で失敗注入が間に合わない場合、workerを個別に止めてから申請する。システム時計は変更しない。

「操作前後を比較」で現在の残高・オーソリ・台帳・APIログ・配信履歴を読み取り保存できる。通常画面で操作後に戻り「操作後を取得」。比較は同じブラウザタブのメモリーに保持し、再読み込みで消える。workspace/generation別に分離し、PWAキャッシュには保存しない。

各シナリオの自動検証は上表のテスト名（`pnpm run test` と `pnpm run test:e2e`）で実行できる。手動操作の手順は同じ結果をPortal・ECの画面から再現する。要件ごとの対応は [requirements-matrix.md](requirements-matrix.md)、最終実行結果は [completion-report.md](completion-report.md) に記録する。テストを実行していないシナリオを合格とは扱わない。
